# 配对与局域网通道

这一篇讲清手机和桌面是怎么连上的、票据里有什么、为什么只信任指纹而不是证书链，以及连不上时按什么顺序排查。上手步骤在 [GETTING-STARTED.md](GETTING-STARTED.md)。

![配对与首连的八个步骤](diagrams/pairing-flow.png)
示意图：一次配对 = 一张 90 秒票据 + 一次 ECDH + 一次指纹固定；之后每一帧都加密。

## 它是怎么连上的

桌面开一条局域网 WSS 通道，用自签证书；手机拿到票据里的证书指纹后只信任那张证书。配对本身是一次 ECDH：双方各出一份密钥，算出同一个共享秘密，再把它派生成双向的会话密钥。

整个过程分八步：

1. 手机生成配对请求 `MORROWPAIR1.<base64url>`，里面是本机公钥。
2. 桌面签发票据：`desktopPub`、`nonce`、`exp`、`relayHint`、`fingerprint`。
3. 手机校验这张票是不是给自己的（票据里的公钥必须等于本机公钥），再用 ECDH 算出共享秘密。
4. 手机连 `relayHint` 指向的地址，校验证书 SHA-256 指纹是否等于票据里的值。
5. 手机发 `hello`，用 `HMAC-SHA256(sessionKey, deviceId + 通道 + 时间戳)` 做鉴权。
6. 桌面回 `welcome`——这是整条链路上唯一一帧明文，内容是盐、最新序号与是否要补快照。
7. 双方用 HKDF-SHA256 派生出两个方向的密钥。
8. 之后每一帧都是 AES-256-GCM 密封的，认证数据里带方向与计数。

## 票据字段

| 字段 | 含义 | 手机怎么用 |
|---|---|---|
| `deviceId` | 桌面给这台手机分配的 id | 连接与撤销时标识设备 |
| `pubKey` | 手机上报的公钥 | 必须等于本机当前公钥，否则判为「不是本机的票」 |
| `desktopPub` | 桌面的公钥 | 用来算 ECDH 共享秘密 |
| `nonce` | 一次性随机值 | 桌面凭它完成配对，票据随即作废 |
| `exp` | 过期时间 | 超过就报「配对码已过期」 |
| `relayHint` | 局域网地址 `host:port` | 手机连它；缺了会明确报「配对信息里没有中继地址」 |
| `fingerprint` | 桌面自签证书的 SHA-256 | 连接时逐字比对 |

票据 90 秒有效、一次性。六位码在手机本地比对，最多错 3 次；错了 3 次这张票作废。

## 六位码与证书指纹

这是两件事，容易被混成一件：

- **六位码**回答「桌面那边是不是我刚才操作的那个人」。它由共享秘密派生，手机本地算一遍、和桌面显示的数字比。
- **证书指纹**回答「我连上的服务器是不是票据里那台电脑」。桌面的证书是自签的，没有可信链可查，所以手机固定指纹而不是校验 CA。

两个都过，连接才算建立。只过其中一个都不行。

## 局域网范围

通道只监听局域网地址，手机必须和电脑在同一个网段。公网中继是占位实现，从未承载过手机流量，因此跨网络不可用。

由此带来几条实际约束：

- 手机用移动数据、电脑在另一个网络时连不上。
- 开启 VPN 或旁路由会改变网段，常见表现是「在线突然变已断开」。
- 路由器开了 AP 隔离（客户端隔离）时，同一 Wi-Fi 下也连不通。
- 桌面防火墙拦掉端口时，表现为握手超时而不是报错。

## 断开与撤销

关闭码 `4401` / `4402` / `4403` 表示鉴权失败、票据无效、设备已撤销。收到这三个码时手机直接停止，不重连——继续重试只会刷屏。

普通断网（切后台、锁屏、路由器抖动）不会作废配对。手机保留凭据并在回到前台时重连；重连后桌面补一份快照，把断线期间的事件一次对齐。

撤销在桌面做：**设置 → 手机配对 → 已配对设备**，撤销后那张票据与那份会话密钥一起作废，手机下次必须重新配对。手机上「清除配对」只清本机凭据，不会通知桌面。

## 排错

| 现象 | 先看什么 | 怎么处理 |
|---|---|---|
| 一直停在未配对 | 桌面远程通道是否打开 | 回桌面「设置 → 手机配对」打开通道，再重新生成配对码 |
| 提示不是本机的配对码 | 票据里的公钥是否属于这台手机 | 在手机上重新复制配对请求，让桌面用新的重签 |
| 提示配对码已过期 | 是否超过 90 秒 | 回桌面重新生成；旧码不会复活 |
| 提示缺中继地址 | 桌面是否开启了局域网通道 | 检查端口占用与网卡，再重新生成票据 |
| 证书指纹不匹配 | 是否换过电脑或重装过桌面 | 撤销旧设备后重新配对，不要忽略这个提示 |
| 面板显示已配对但手机离线 | 是否同一局域网、是否开了 VPN | 关 VPN，确认同一路由器且未开 AP 隔离 |
| 断线后一直重试 | 关闭码是否 4401/4402/4403 | 直接停止重连，回桌面撤销后重新配对 |

## 协议与安全细节

- 帧格式：外层 JSON 信封，内层密文；方向（`phone-to-desktop` / `desktop-to-phone`）、设备 id 与严格递增的计数都作为 AAD。
- 密钥派生：ECDH P-256 → HKDF-SHA256，`info` 里带方向与设备 id，所以两个方向的密钥不同。
- 重放防护：计数严格递增，重复计数直接拒绝。手机与桌面各自记录已见的最大序号。
- 凭据存储：会话密钥、设备私钥、桌面地址与指纹写在 Android Keystore 加密的文件里；Keystore 不可用时配对失败并说明原因，不降级成明文保存。
- 通知深链：`morrow://approvals` 与 `morrow://activity` 只由应用自己的显式 Intent 触发。清单里刻意不声明 `VIEW` intent-filter，否则任何应用都能构造链接唤起本应用。

只在本机局域网内可用：公网中继尚未实现。撤销配对等于作废会话密钥，下次连接必须重新配对。
